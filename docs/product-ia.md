# Moho 产品信息架构（v1.6）

> 这份文档只讲产品逻辑：用户要做什么、产品里有哪些对象、信息分几层露出。
> §6 的决策已确认（2026-11-07），按推荐方案执行。

---

## 0. 一句话定位

**让该走代理的流量走最好的出口、其余直连；同时让用户随时知道现在是什么状态，出了问题能自己定位。**

由此得出三条设计原则，后面每个决定都要对得上：

1. **状态先于控制**：先告诉用户"现在是什么情况"，控制只出现在对应的状态旁边。
2. **正常时安静，异常时显眼**：一切正常时界面应该很平静；只有出问题时才弹出提示。不常驻告警卡片。
3. **每条信息只有一个家**：同一个信息只在一个地方完整展示，其他地方只放摘要并链接过去。

## 1. 核心对象模型

所有界面都是在看同一条链路：

```
应用 ──► 入口 ──► 规则 ──► 路由 ──► 节点 ──► 互联网
(谁)    (怎么进来) (怎么判断) (该去哪类出口) (具体走哪台机器)
                                      ▲
                                  Provider（节点从哪来）
```

| 对象 | 是什么 | 用户关心的属性 | 用户能做的操作 |
|---|---|---|---|
| **入口** Entry | 流量怎么进入 Moho：系统代理、TUN、本地端口 | **是否真的生效**（不是"开关开了没"） | 选择接管方式；修复异常 |
| **规则** Rule | 判断一条请求属于哪条路由：域名 / GeoSite / IP / 进程 | 命中了哪条 | 查看；少数情况下新增或修改 |
| **服务** Service | 一个网站或产品需要的一组规则，例如 Claude、Netflix。一条规则只属于一个服务，一个服务只属于一个路由组 | 属于哪个路由组 | 移动、停用、新建 |
| **路由** Route | 一类流量的去处，例如「AI 服务」「流媒体」「默认」「直连」 | **当前出口节点、健不健康** | 换节点、换选择策略 |
| **节点** Node | 一台具体的出口服务器 | 地区、延迟、稳定性 | 选中、测速 |
| **Provider** | 节点的来源：订阅链接、单节点链接、本地文件 | 能不能用、还剩多少流量、什么时候到期 | 添加、更新、停用、删除 |
| **模式** Mode | 对「规则」这一步的全局覆盖：规则 / 全局 / 直连 | 现在是不是特殊模式 | 临时切换 |
| **内核** Core | mihomo 进程 | 只关心"是否正常" | 重启、更新（极少） |

**命名统一**：界面上只用「接管、入口、路由组、服务、节点、Provider、规则、模式」这几个词（「路由组」就是这里说的路由）。不出现「代理组」「策略组」「Selector」这类 Clash 术语，它们只出现在高级视图里。

### 1.1 关于「路由」

Clash 的「代理组」是实现层面的概念：组可以嵌套、类型一大堆。用户脑子里的模型其实是：

> **「这类流量」→「走这个出口」**

所以路由的主表达就是一句话：**`AI 服务 → 🇺🇸 洛杉矶 VPS · 168 ms`**。
怎么挑节点（自动最快 / 顺序备用 / 固定节点）、候选节点有哪些、命中哪些规则，都属于第二层信息。

## 2. 状态模型（回应第 4 点）

你说得对：系统代理、TUN 不应该做成开关，它们应该是**状态**。

用户真正的操作只有一个：**接管 开 / 关**。用哪种方式接管（系统代理 / TUN / 两者都用）是偏好设置，很少改。界面要如实反映的是每个入口的**真实状态**，而不是用户点过什么：

| 入口 | 可能的状态 |
|---|---|
| 系统代理 | 未使用 · **生效中** · **被其他程序改掉了**（系统代理已不指向 Moho） |
| TUN | 未使用 · 需要安装服务 · **生效中** · 异常（服务掉了、权限丢了） |
| 本地端口 | 监听中 `127.0.0.1:7899` · 端口被占用 |

把这些合成一个**总状态**，全产品只有这一个灯：

| 总状态 | 条件 | 表现 |
|---|---|---|
| ⚪ 未接管 | 用户关了接管 | 灰色，提示"应用直接连接互联网，除非代理指向 Moho 的端口" |
| 🟢 正常 | 至少一个入口生效，内核正常，各路由当前节点都可用 | 安静，只显示出口和速度 |
| 🟡 降级 | 能用，但有问题：某路由的节点在超时、发生了故障转移、Provider 快到期 | 一句话说明问题 + 一个处理入口 |
| 🔴 异常 | 流量实际走不通：内核挂了、入口被改了、所有节点都不可用 | 显著提示 + 一键修复（例如"重新接管"） |

> **未接管不等于没有流量。** 接管关着时内核和本地端口照常工作，把代理手动指向本地端口的应用，流量仍然经过 Moho。所以"未接管"只描述入口，不描述流量：事件、流量图、连接数、菜单栏面板的网速都按**实际观察到的**连接和历史来显示，不看接管开关；只有什么都没观察到时才显示"没有流量"一类的空闲文案。任何时候都不能在列着连接或历史的地方写"流量不经过 Moho"。菜单栏面板（和 Linux 的托盘菜单）在未接管但观察到流量时也列出节点：这些流量从这里选的节点出去。
>
> 这里的"状态"需要客户端**主动检测**：比如定时检查系统代理是否还指向自己，因为其他 VPN 或代理软件经常会把它改掉。这是 Clash 系客户端普遍缺失、而用户很需要的能力。

## 3. 任务分析

按频率从高到低排，决定每个任务放在哪一层：

| # | 用户任务 | 频率 | 典型触发 | 放在哪层 |
|---|---|---|---|---|
| T1 | 确认现在正常、走的哪里 | 持续 / 每次看 | 下意识瞥一眼 | **L0 菜单栏** |
| T2 | 看当前速度 | 持续 | 下载东西时 | **L0 菜单栏** |
| T3 | 打开 / 关闭接管 | 每天 | 开会、用公司网络 | **L0 菜单** |
| T4 | 给某类流量换个节点 | 每周几次 | 节点慢了、想换地区 | **L0 菜单**（快捷）/ **L1** |
| T5 | 临时切全局或直连 | 偶尔 | 排查、临时需要 | L0 菜单 / L1 次要位置 |
| T6 | 处理异常（节点挂了、被改了、到期） | 偶尔但紧急 | 异常提醒 | 提醒在 **L0 / L1**，处理在 **L2** |
| T7 | 排查"某网站打不开 / 走错出口" | 偶尔但关键 | 网页打不开 | **L2 活动** |
| T8 | 测速、挑节点 | 偶尔 | 选节点前 | **L2 路由详情** |
| T9 | 添加或更新 Provider | 每月 | 买了新机场 | **L2 Provider** |
| T10 | 让某个域名走某条路由 | 少 | 排查之后 | **L2**（从活动里一键生成规则，规则落在该路由组的「我添加的」） |
| T11 | 新建或编辑路由组、服务、规则 | 很少 | 重度用户 | **L2 路由组 Tab** |
| T12 | 端口、TUN 服务、内核、开机启动 | 很少 | 首次设置 | **L3 设置** |

## 4. 渐进式披露

| 层 | 载体 | 回答的问题 | 内容 |
|---|---|---|---|
| **L0** 一瞥 | 菜单栏图标 + 下拉菜单 | "正常吗？" | 图标只分亮 / 暗（接管开 / 关），旁边默认不放网速（设置里可以打开，见下）；面板里一级就是换节点、接管开关、模式三件事（不放路由，路由在主窗口），没有动画；打开主窗口 |
| **L1** 一屏 | 主窗口首屏，不用滚动 | "现在什么情况？" | 总状态 + 出口；实时流量；路由一览（每条一行）；只在有问题时出现的异常条 |
| **L2** 详情 | 抽屉、详情页、Tab | "为什么？怎么改？" | 路由详情（候选节点、策略、命中规则）；路由组（服务、规则、节点策略）；活动（连接 / 日志）；Provider 详情；入口状态详情 |
| **L3** 高级 | 设置、高级编辑 | "我要定制" | 端口、TUN 服务、内核、原始配置 |

**L1 只有一屏**：如果首页需要滚动，说明 L1 放了 L2 的内容。

### 4.1 每一层的内容清单（L0 / L1 详细）

**L0 菜单栏**

```
[图标]                              ← 亮 = 已接管，暗 = 未接管；不带角标，默认不带网速
──────────────────────────
● 正常 · 全局模式             [■]    ← 总状态 + 唯一的开关；开关生效、内核启动期间状态字 shimmer
↓ 2.5 MB/s  ↑ 212 KB/s    今日 2.4 GB
──────────────────────────
节点                                  ← 「其他流量」出口的节点，就地列出，点一下就换
✓ 自动  最快 + 故障转移
  🇭🇰 香港 03 IPLC       当前  41ms
  🇭🇰 香港 02                  64ms
  …最快的 8 个
  全部节点…                    42 个
──────────────────────────
模式               规则 / 全局 / 直连
──────────────────────────
打开 Moho                      ⌘O
退出 Moho                      ⌘Q
```

图标旁默认什么都不放：看网速点开面板。想一直看着网速的人可以在「设置 › 通用」里打开「在菜单栏显示网速」，接管时（或者未接管但有连接经过本地端口时）图标旁多一段定宽的文字（`↓1.3M ↑ 60K`，没人看着时每 2 秒更新一次）；Windows 的托盘图标旁放不了文字，网速放在悬停提示里；Linux 上只有会显示 indicator 文字的面板才看得到。

面板不放路由：给某条路由换节点在主窗口（L1 / L2）。面板里没有动画，点开、切换、关闭都直接到位。

**L1 主窗口首屏**（v1.2 修订：按"杂志 + 可视化"组织，三层重要性从上到下）

| 层 | 内容 | 表现 |
|---|---|---|
| ① 标题级 | **当前出口节点**、**代理模式**、**接管方式** | 出口用大号衬线标题（"香港 03 IPLC"）+ 延迟和稳定性；右侧是一张出口地图，从"你"出发，每条路由一条弧线，粗细代表流量，光点代表正在传输的数据 |
| ② 就地切换 | 换节点 / 自动选最快；模式 规则·全局·直连；接管 系统代理·TUN；各分流路由的出口 | 不另开页面：点节点名弹出按延迟排序的列表；模式和接管方式是"可点的词"，选中的为实色并带下划线 |
| ③ 状态与监控 | 此刻速度（按路由着色的柱图）、谁在用、刚刚发生了什么（实时事件流） | 小字号、高密度；"全部活动 →" 进入活动页 |
| 快讯条 | 仅降级或异常时出现在标题栏下方 | "异常 · 系统代理被其他程序改掉了 [重新接管]" |

> 修订说明：v1.1 把"实时速度"放在最显眼的位置，但用户打开主窗口最想确认的是"走哪个出口、什么模式、怎么接管的"，速度属于第三层。

**L2 路由详情**（从 L1 点进来）

1. 头部：路由名 → 当前节点、健康度、选择策略
2. 候选节点：按地区分组，显示延迟和稳定性（最近 N 次测速）
3. 命中的规则：摘要，例如"openai.com、anthropic.com 等 12 条"，可以展开
4. 这条路由当前的连接：链接到活动页，并带上筛选条件

**L2 活动**：连接 / 日志 两个 Tab，共用筛选（应用、路由、失败）。
从一条连接可以一键"让这个域名走 XX 路由"，这一步会生成规则，放进该路由组的「我添加的」，在路由组 Tab 里管理。

**Provider：第三个 Tab**（v1.3：弹窗改为 Tab）。上方是添加栏（粘贴订阅链接或节点链接，自动识别；也可以选本地文件），下方是 Provider 列表：用量、到期、节点延迟分布、自动更新、更新 / 停用；点开一行显示它的全部节点、实测出口位置、被哪些路由使用。在任何页面按 ⌘V 粘贴链接会跳到这里并填好内容。

## 5. 导航结构

```
Moho
├── L0 菜单栏
└── 主窗口
    ├── 代理（L1）                 ← 默认页；每个区块都能原地展开（L2）
    │   ├── 出口 → 选择出口  ← 地区筛选、搜索、全部测速、自动 / 手动
    │   ├── 地图 → 各路由出口一览
    │   ├── 模式 → 模式与规则
    │   ├── 接管 → 系统代理 / TUN / 本地端口的详细状态和开关
    │   ├── 分流 → 路由一览 → 某条路由的选择出口
    │   └── 速度 / 谁在用 / 刚刚 → 各自的完整视图
    ├── 活动（L2）：连接 | 日志
    ├── Provider（L2）：添加 + 列表
    ├── 路由组（L2，⌘4）：路由组 → 服务 → 规则，节点策略，测试一个地址
    └── 设置（L3，⌘, 独立窗口）
        ├── 接管方式（系统代理 / TUN / 两者）、端口、局域网
        └── 通用：开机启动、外观、内核
```

**首次启动**：窗口打开时一个来源都没有，就不显示标签页，而是整窗的初始化页，分两步：添加节点（和 Provider 的添加栏收同样的内容）、选择接管方式。接管后或点跳过进入今日。只在窗口打开时判断一次，之后删光来源仍留在 Provider 页。

**对导航形式的影响**（回应第 3 点）：顶层只有 3–4 个目的地，而且 L1 就能完成大多数任务，所以**不需要常驻侧边栏**。标题栏里放一个分段控件，或者用工具栏图标就够了，主内容可以占满宽度。具体形式到界面阶段再定。

## 5.1 交互约定（v1.3）

- **区块原地展开（morph + 挤压）**（v1.4，取代 v1.3 的底部抽屉）：首页是一整张网格面板，被点的区块在面板里原地长大，同一行的区块被压窄，同一列的被压矮，其余的两个方向都被压缩；被挤压的区块换成"摘要"视图（标签 + 一个最重要的值），点它可以直接切过去。每个区块有三种视图：正常（固定尺寸，挤压时不重排、只淡出）、摘要、展开，三者交叉淡入淡出；展开内容第一次出现时逐行错开浮现。地图在形变过程中按实时尺寸重绘。Esc 或 × 收起。
- **未接管时收拢**：未接管时面板只剩标题区和地图：大字"未接管"、一句说明、两个接管方式（系统代理 / TUN）和"上次使用"。其余区块的行高收为 0；接管成功后整个面板展开回来。
- **被挤压的区块必须完整**（v1.6）：先算出每个区块形变结束时的尺寸，再按尺寸选版式，内容按版式设计成一定放得下，不靠截断：
  - 窄矮：标签 + 一个短值（如"实时"、"■■■ 3 条"）；
  - 宽矮：标签，下一行是值 + 一句说明；
  - 窄高：标签、值、说明、列表，允许换行；
  - 宽高：同窄高，值的字号更大。
  原型里逐一检查了 8 种展开状态下所有被挤压的区块，零溢出。
- **视图在最终尺寸下排版，像抽屉一样开合**（v1.6）：每个视图（正常 / 摘要 / 展开）都固定为它所在区块在最终状态下的尺寸，比如行一开始就是全宽，形变过程中不重排、文字不被挤压。新视图在预期位置由上而下逐行拉开；离开的视图按自己原来的尺寸向上收起，然后才清空。
- **顶栏**（v1.6）：标题栏和内容之间不画分隔线，二者是同一张纸；Tab 做成一个分段控件，当前项是墨色实底；右侧状态也是同形制的小药丸。
- **共享元素过渡：不交叉淡化，"实"的形变**（v1.5）：
  - 同一个东西在每个视图里有同一个身份（`data-m`），比如每个区块的标签、出口节点名、路由名、接管方式、模式下划线、应用名、速度。
  - 切换时先量出旧位置，再量出最终布局（网格动画的终点），然后用一份**真实文字**的克隆从旧位置飞到新位置，字号、颜色、字距逐帧插值。文字每帧重新排版，始终清晰；真实元素在落地前隐藏，所以任何时刻每样东西只出现一次。
  - 文字内容变了：原地的用遮罩滚动替换（旧的向上滑出，新的从下方滑入）；位置也变了的，旧文字在原处被擦除，新文字边飞边擦入。
  - 视图之间不做透明度渐变：旧视图立即隐藏，新视图随卡片长大被"露出"，非共享的行带短促的上浮错开进入。
  - 地图弧线、粗细、透明度缓动到新目标。
  - 不用 View Transitions：它是新旧两张位图的交叉淡化加缩放，会有重影，文字也会发糊。
- **加载态用流光（shimmer）**：所有需要时间生效的切换，在生效前把对应的文字做成流光，不用转圈。包括：系统代理 / TUN 开关（TUN 首次还要安装提权服务，文案提示"请在系统弹窗中确认"）、换节点（标题和延迟同时流光）、切模式、测速（延迟数字变成骨架条）、更新 Provider、重新接管。
- **活动页的查询能力**：搜索支持 `app:` `route:` `node:` `host:` 语法，其余词匹配任意字段；按状态（活跃 / 已关闭 / 失败）、路由、应用、TCP/UDP 筛选；速率、下载、上传、时长可排序；可以暂停实时刷新；"断开筛选结果"需要二次确认；点一行展开详情（进程路径、目标 IP、规则、完整链路、出口、错误），可以直接"让这个域名走…"生成规则。日志同样支持级别筛选、搜索、暂停、导出。

## 5.2 出口位置从哪来（地图的前提）

节点配置里**没有可靠的地理位置**，只能推断或测量。按可信度排列：

| 来源 | 做法 | 可信度 | 成本 |
|---|---|---|---|
| **实测** | 经该节点访问一个回显服务（如 Cloudflare `/cdn-cgi/trace`，返回出口国家和最近机房代码，例如 `loc=HK colo=HKG`） | 高：测的就是真实出口 | 每个节点一次请求；只测当前在用的节点和用户点开的节点，结果缓存 |
| **按名称** | 解析节点名里的国旗 emoji、国家 / 城市名、地区代码（"香港 03""🇯🇵 Tokyo""SG-01"） | 中：机场节点大多这样命名 | 零成本，作为默认值 |
| 服务器 IP 的 GeoIP | 查节点服务器地址所在地 | **低**：IPLC、中转、CDN 前置时，入口不等于出口 | 不采用，只作参考 |
| 未知 | 以上都没有 | — | 地图上显示虚线和"定位中"，测完再落点 |

实现思路：mihomo 的 `listeners` 可以把一个入站端口绑定到指定代理组；Moho 内置一个探测用的选择器组和专用端口，探测某个节点时把组切到该节点，再经这个端口请求回显服务。界面上用「实测 / 按名称 / 未知」标签标明来源。

地图本身按"方向"画，不按真实距离：以东亚为主视野，太平洋对岸的出口放在右边缘、欧洲等放在左边缘，用箭头标注。以后如果用户在其他地区，视野按"你"和当前出口的范围自动调整。

## 6. 已确认的产品决策

| # | 决策 | 结论 |
|---|---|---|
| D1 | 节点来源和路由规则分开 | **默认分开**。Provider 提供节点；路由和规则由 Moho 管理，内置默认模板（其他流量、AI、流媒体、开发、直连）。带 `proxy-groups` 的配置在 Provider 行提示「使用它们」，由用户显式开启，订阅更新绝不自动切换；同一时刻只有一份配置生效。开启后这份配置的组和规则原样生效，规则指向的组显示为路由，只有手动选择（select）的组可以切换；你的规则和规则集暂停，改回后恢复。这是唯一会在界面上出现配置自带组的地方。 |
| D2 | 首页放不放「活跃应用」 | **不常驻**。L1 只在某个应用流量异常大时提示一句；完整列表在 L2 活动页。 |
| D3 | 路由选择策略 | 每个路由组三选一：**自动最快**（url-test，可限定地区 / 来源；范围里没有节点时变红，不悄悄放宽）、**顺序备用**（fallback，按排好的顺序）、**固定节点**（不自动切换，不通时提示）。切换策略只移动选择器，不重载配置；每种策略的设置切换后保留。地区行优先显示全局的**常用地区**（默认取节点最多的 6 个，可在行内增删、排序），其余折叠在「更多」里，已选中的地区始终显示。常用地区只决定显示，不改变任何路由组的范围。 |
| D4 | 用户新建路由 | **支持**，入口在主窗口的路由组 Tab。结构（路由组 / 服务 / 规则）只在这里编辑；节点策略在这里和代理页的原地展开共用同一个组件。规则按具体程度排序：DOMAIN > 更长的 SUFFIX > 更长的 KEYWORD > GEOSITE > 更长的 IP-CIDR > GEOIP，同级时用户的规则优先。导入规则集（一个来自链接或文件的服务）后，顺序固定为：你的规则 → 规则集 → 内置规则。规则集之间按列表从上到下匹配：先看路由组的位置，再看它在组里的位置，「其他流量」里的排在最后。路由组和同组的规则集可以拖动调整顺序；「直连」「拦截」「其他流量」固定在最后。路由组的位置对其他规则只在同样具体时起作用。 |
| D4a | 没命中规则的流量 | 路由组叫**其他流量**（内核里的组名仍是「默认」），排在最后。出口二选一：**走节点**（三种节点策略）或**直接连接**（`MATCH,DIRECT`）。直接连接只作用于规则模式，节点策略保留，全局模式仍按它走节点。路由组顺序不可编辑：规则按具体程度排序，组序只在同样具体时打破平局。 |
| D5 | 平台 | **先做 macOS**；最终覆盖 macOS、Windows、iOS、Android。见 §8。 |
| D6 | 界面技术 | **MyGo 原生 UI**（Go 编写、GPU 绘制，不用 WebView）。形变用元素盒子的过渡，共享元素用 `Match` 加文字形变，地图用 `Draw` 绘制。HTML 原型只作为设计参考。 |

## 8. 多平台

信息架构四个平台通用；区别在 **L0 的载体**和**入口**：

| | macOS | Windows | iOS | Android |
|---|---|---|---|---|
| L0 一瞥 | 菜单栏图标 + 弹出面板 | 托盘图标 + 弹出面板 | 控制中心按钮、锁屏 / 桌面小组件 | 快捷设置磁贴、常驻通知 |
| L1 / L2 | 主窗口 | 主窗口 | App 首页 + 导航栈 | App 首页 + 导航栈 |
| L3 | 设置窗口（⌘,） | 设置页 | 设置页 | 设置页 |
| 入口 | 系统代理 / TUN / 端口 | 系统代理 / TUN / 端口 | **只有 VPN**（Network Extension） | **只有 VPN**（VpnService） |
| 内核运行方式 | 独立进程（sidecar） | 独立进程（sidecar） | 作为库跑在 Network Extension 里 | 作为库跑在 VpnService 里 |

**对技术选型的影响（以后再定，不影响 macOS 第一版）**

- **MyGo 只支持桌面端**（macOS / Windows / Linux），iOS 和 Android 需要另外的界面方案：原生（SwiftUI / Compose），或者跨四端的框架。
- 不管界面用什么做，**产品逻辑层都应该写成平台无关的 Go 包**，四端复用，例如路由模板、Provider 管理、状态判定、规则生成。现在 macOS 版就按这个边界来写。
- 移动端必须把 mihomo **作为库链接进 App**（不能起子进程），所以 App 会受 GPL-3.0 约束，需要开源。iOS 的 Network Extension 还有约 50 MB 的内存上限，要专门优化。
- 移动端只有 VPN 一个入口，§2 的状态模型照样成立，只是入口那一行只有一项。
